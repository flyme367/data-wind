# 渲染 Worker 化：JS 开启多线程 work

## Context

在 IAB（无 WebGPU → Rust CPU 兼容渲染）里插入「科技风3D城市」（49 栋楼）后页面整体卡死：所有 wasm 调用都在主线程。探查确认三处主线程 rAF 循环——编辑器 Viewport、viewer canvasHost、看板 RustBoardHost——CPU 路径每帧同步执行 `JSON.stringify` 全量实例 + wasm 软光栅 + `putImageData`；看板侧每秒强制重绘 + 拖拽时每帧 `sync_scene`。rayon parallel 构建（wasm-bindgen-rayon + SAB）已落地但只并行化像素填充，`frame()` 同步调用本身仍占主线程。

目标：把 **3D CPU 兼容渲染**和**看板 CPU 画布**整体搬进 Web Worker（OffscreenCanvas），主线程只保留交互、相机、数据编排；crossOriginIsolated 时 worker 内用 parallel 构建多核光栅。GPU（WebGPU）路径不动。

## 方案总览

```
主线程（交互权威）                         渲染 Worker（每宿主一个实例）
Viewport / CanvasHost ──post──►  scene3d worker: wasm SoftwareCanvas
  · 相机/拖拽/飞行补间(主 rAF 保留)      · 自驱 setTimeout 渲染环（自 pacing ≈30fps 上限，隐藏页暂停）
  · runtimeFlat → post flat(变更时)     · JSON.stringify 在 worker 内、每场景变更一次
  · 指针事件转发 / 异步 pick(reqId)      · OffscreenCanvas 2D ctx 直接 putImageData
  · 快照请求(reqId) → 组装滤镜导出       · parallel 构建时 rayon 多核分带光栅
RustBoardHost ──────────post──►  board worker: wasm BoardCanvas(cpu)
  · 异步 hit_test(reqId)→光标/选中      · sync_scene/frame/hit_test/pointer/set_image/
  · 媒体像素解码(主线程)→transferable     snapshot/set_value/take_events 全量代理
    ArrayBuffer 传输（限频）             · putImageData 到 transferControlToOffscreen 的 cpuCanvas
```

## Phase A：3D 软渲 Worker（无 Rust 改动）

1. **新增 `frontend/src/engine/engineWorker/protocol.ts`**：两个角色的消息类型联合（init/scene/camera/resize/pointer/pick/snapshot/registerModel/stats/hidden…），请求-响应配对用 `requestId`（复用 `bridge.ts` 的 checkpoint 配对模式，抽成可复用小工具）。
2. **新增 `frontend/src/engine/engineWorker/render.worker.ts`**：
   - wasm 初始化镜像 `engineClient.ts:20-35`：worker 内 `crossOriginIsolated` 判定 → `../wasm/parallel`（`initThreadPool(min(4, cores-2))`，避免与主线程池叠加爆线程）→ 失败回退 portable。
   - `role: "scene3d"`：持 `SoftwareCanvas`；收到 `scene`（flat 数组）后 stringify 缓存；自驱渲染环：每帧收主线程最新 camera/options，`frame()` → `putImageData` 到 OffscreenCanvas；`pick` 请求同步返回；`snapshot` 渲染后 transfer 回 `ArrayBuffer`；每 500ms 上报 `{fps, instances}`。
3. **新增 `frontend/src/engine/engineWorker/sceneRenderClient.ts`**：与 `SoftwareRenderer`（softwareRenderer.ts:57-94）同接口的主线程客户端：`render→post`、`pick→Promise`、`renderSnapshot→Promise<bytes>`、`registerModel→post(bytes 结构化克隆)`；`transferControlToOffscreen` 不可用或 worker 初始化失败 → 返回现主线程 `SoftwareRenderer`（保留为回退）。
4. **改 `frontend/src/components/Viewport.tsx`**（软件分支）：
   - `fallbackCanvas.transferControlToOffscreen()` 交给 worker；主 rAF 只做飞行补间/句柄投影，每帧 post camera，`flat` 变更时 post（`useMemo` 已有）。
   - 拾取异步化：pointerdown 先按 orbit 处理，pick 响应到达（几 ms）后若是可编辑模型升级为 move；pointerup 的点击 pick 走 requestId（canvasHost.ts 同理，它没有 move 逻辑，更简单）。
   - 截图（`registerSceneCapture` 软件分支）改为 worker snapshot → 主线程按现状合成滤镜输出。
   - stats 用 worker 上报值替换本地帧计数。
5. **改 `frontend/src/viewer/canvasHost.ts`**：同 4（无 move 拖拽，改动更小）。

## Phase B：看板画布 Worker（含一处 Rust 改动）

6. **Rust `engine-rs/data-wind-engine/src/board_canvas.rs`**：现 `BoardCanvas::create(canvas: HtmlCanvasElement, gpu)` 无法在 worker 使用——新增 CPU-only 构造入口 `create_cpu_offscreen(offscreen: web_sys::OffscreenCanvas)`（复用现有 CPU 分支逻辑；`Cargo.toml` web-sys features 增加 `OffscreenCanvas`）。纯 TS 侧改动之外的唯一 Rust 触点。
7. **改 `frontend/src/engine/boardCanvas.ts`**（`RustBoardHost`）：
   - GPU 路径不变（probeWebGPU 健康 → 主线程 `BoardGpu` 照旧）。CPU 路径：`cpuCanvas.transferControlToOffscreen()` → board worker（portable 构建，看板帧已 dirty 门控，单线程够用）。
   - 异步化三处同步 surface 调用：`hit_test`（root 悬停/按下，响应驱动 pointerEvents/光标，reqId 配对）、`frame`（worker 绘制后回 `painted` ack，主线程清 dirty）、`snapshot`（bytes 回传）。`take_events/pointer/set_value/focus_node/activate/set_geojson/set_status/set_image/clear_image` 一并代理转发。
   - 视频像素：主线程解码不变，`set_image` 改为 transferable `ArrayBuffer` postMessage 并限频（~10fps）避免大帧拷贝卡消息通道。
   - 回退：worker 初始化失败 → 现主线程 CPU 路径原样保留。

## 不动的部分

- WebGPU 两条路径（3D `Engine`、`BoardGpu`）：主线程照旧。
- 主线程 wasm 初始化（engineClient.ts）与 scene.worker/assets.worker。
- `sync_scene`（GPU 路径）的 stringify——非卡顿源头。
- 构建脚本 build-engine.mjs、vite 配置（COOP/COEP、`worker.format:"es"` 已就绪）。

## 验证

1. Rust 改动后重建两份 wasm：`pnpm build:engine:single` + `build:engine:parallel`（注意 cargo 不在 PATH，用 ~/.cargo/bin；parallel 需 nightly-2026-04-15 + rust-src，见 docs/rayon.md）。
2. `tsc --noEmit`、`oxlint`、`vitest` 全绿；新增 protocol/client 单测（消息配对、回退判定，vitest 环境不可建真 Worker，抽纯函数测）。
3. IAB 实测（dev 5173，天然无 WebGPU，vite 头 → crossOriginIsolated）：
   - 打开项目 → 状态栏 Rust/CPU + worker 生效；插入「科技风3D城市」49 楼 → **主线程不再卡死**（evaluate/交互可响应），轨道/平移/缩放/点选/撤销正常，FPS 由 worker 上报。
   - 看板组件：渲染、时钟每秒重绘、拖拽/缩放、控件交互、视频/图片组件、看板快照导出。
   - 3D 与看板的截图导出（snapshot 走 worker）。
   - 测试残留清理：验证用临时项目「面板巡检-临时」如有上次会话插入的城市场景，撤销/清空。
4. WebGPU 回归：本机 Chrome（WebGPU 可用）打开同一项目 → 3D/看板仍走 GPU 主线程路径，无 worker 创建。

## 风险与回退

- `transferControlToOffscreen` 后主线程不能再读该画布——快照已改为 worker 渲染，无读回需求；CSS filter 仍作用于 canvas 元素。
- 双 wasm 实例内存（主线程 + worker 各一份）与 rayon 池叠加——worker 侧限线程数（min(4, cores-2)）、board worker 用 portable；不足再调。
- 拾取异步化引入 ≤1 帧延迟（orbit→move 升级、悬停光标），实测确认手感，不达标则对 pick 做预测缓存。
- 任一环节失败自动回退现有主线程渲染，功能等价于现状（只是会卡），不产生新故障面。
